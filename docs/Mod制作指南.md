# 无限工厂3 Mod 制作指南

适用于无限工厂3 0.2.3，Mod 格式为 1。一个包可以包含卡牌、配方、外观、声音和玩法脚本。

## 先体验一个完整例子

下载[苔光花园示例](../examples/mods/苔光花园.wxgc3-mod)，在主页点「Mod → 导入 Mod 文件」，选中下载的文件，再点「安装 Mod → 启用」。在工厂里也可以从「更多 → Mod」进入。这个包提供一张种子、两条固定配方、园艺合成主题、苔绿台布、叶脉卡面、花房卡背和提示音，以及“收一颗种子”玩法按钮。

启用后可以从词典把“种子”放上台面；水＋土得到幼苗，幼苗＋木得到花园，两颗种子由脚本合成双生芽。进入外观设置选择包里的台面、皮肤和卡背。游戏自带的五本源开局不变，只有启用此包的存档会增加包里的内容。

合成历史和配方表从“更多”进入。配方表区分已发现配方与已启用 Mod 的预设配方；预设配方还没合成时不会算作发现。历史保留当时的来源，移除包后仍能看到原 Mod 名称。

## 文件与内容

`.wxgc3-mod` 是 UTF-8 JSON，扩展名不同不会改变结构。先复制示例再修改最容易。顶层字段如下：

| 字段 | 含义 |
|---|---|
| `modFormat` | 当前必须为 `1` |
| `id` | 稳定标识，1～48 个小写字母、数字、点、下划线或连字符，首位是字母或数字；更新包不要换 ID |
| `name`、`version`、`description` | 包名、版本文字和简介；版本不自动联网更新 |
| `theme` | 可选的合成主题，加入 AI 请求的材料数据；它不是覆盖游戏安全规则的系统提示词 |
| `cards` | 内容卡定义：`name`、`emoji`、`category`、`description` |
| `startingCards` | 启用时直接加入词典的卡名，需存在于 `cards` 或五本源中 |
| `recipes` | `{"ingredients":["水","土"],"result":"幼苗"}`，支持 2～4 份材料，重复数量保留 |
| `tabletops`、`skins`、`cardBacks` | 外观列表，见下文 |
| `assets`、`sounds` | 包内媒体与音效映射 |
| `script`、`actions` | 可选玩法脚本和玩家可点击的操作 |

分类沿用自然、生物、科技、人文、食物、抽象、整活。卡名最多 32 字，其他文字限制见 `src/content/catalog.js` 与 `src/core/mods.js`。相同名称会复用本档首次发现的卡，不会覆盖原来的图案、简介或分类。不能改写金木水火土的定义。

固定配方按规范化后的材料名称匹配，顺序无关但数量有关。结果需有本包定义或属于五本源；材料可以引用将来才发现的卡。启用的两个包不能给同一组材料提供冲突的固定配方。**本档已经学会的配方优先**，安装新包不会改掉玩家以前发现的答案。要体验另一套相同材料规则，可以新建存档。

## 外观与音效

台面项：`{id,name,color,gridColor,image?}`。卡面和卡背项：`{id,name,face,ink,border,accent,image?}`。颜色使用 `#RRGGBB` 或 `#RRGGBBAA`。`image` 填 `assets` 内的资源 ID。图片作为底纹绘制，游戏继续绘制名字、分类和图案，避免一张图盖住卡牌信息。

资源内嵌为 `data:image/png;base64,...` 等字符串。支持 PNG、JPEG、WebP、WAV、MP3、OGG；不接受 SVG、网页地址、本机路径或脚本文件地址。图片长宽各不超过 2048。`sounds` 的事件名为 `lift`（拿起）、`think`（开始合成）、`discovery`（首次发现）、`repeat`（已知卡）、`failure`（失败），值为音频资源 ID。音频用于短音效，最长 10 秒、最多双声道；无法解码时回到原提示音。启用多个音效包时，列表后面的包覆盖前面的同名事件。

外观标识为 `mod/包ID/tabletops/项ID`、`mod/包ID/skins/项ID` 或 `mod/包ID/cardBacks/项ID`。玩家在外观设置中自选；停用包时退回游戏默认绘制，已发现卡牌不消失。

## 玩法脚本

脚本使用 `registerMod({...})` 注册。所有钩子可省略，可返回普通对象或 Promise。一次调用一个独立 Worker，不保留全局变量；需要跨次保存的内容必须放进 `state`。

```js
registerMod({
  resolve(ctx) {
    // 本地规则：返回 card 时无需调用 AI；返回空值表示没有命中。
  },
  transform(ctx) {
    // 首次答案入档前改写 ctx.result；已知配方不会执行此钩子。
  },
  afterCombine(ctx) {
    return { state: { ...ctx.state, count: (ctx.state.count || 0) + 1 } };
  },
  actions: {
    inspect(ctx) {
      return { message: '已完成 ' + (ctx.state.count || 0) + ' 次合成。' };
    }
  }
});
```

要显示 `inspect` 按钮，还需在顶层 `actions` 写入 `{"id":"inspect","name":"查看记录","description":"看看这个世界的合成次数。"}`。

| 钩子 | 输入 | 可返回的内容 |
|---|---|---|
| `resolve` | 本次材料、当前世界和自己的状态 | `{card?,state?,message?}`；第一个给出卡牌的脚本胜出 |
| `transform` | 上一阶段的结果及相同上下文 | `{card?,state?,message?}`；按启用包顺序处理 |
| `afterCombine` | 最终候选结果及自己的最新状态 | `{state?,message?}`；卡牌返回值不会在此阶段改变答案 |
| `actions[id]` | 当前世界和自己的状态 | `{cards?,state?,message?}`；最多新增 50 张内容卡，不增加合成次数 |

`ctx` 只有 `ingredients`、`result`、`world`、`state`、`operationId`。`world` 包含 `name`、`cards`、`recipes`、`stats`，是本次提交之前的快照；新结果在 `result` 中。动作没有材料和结果。每个包只得到自己的状态，不会取得其他包的状态、API 配置、Key 或本机文件。

先查已发现配方，再查启用包固定配方，再执行脚本 `resolve`，都没有答案时才请求 AI。新答案执行 `transform` 和 `afterCombine`；已知配方只执行 `afterCombine`。`resolve` 没产生卡牌时，其试探性的状态不会保存；将一般计数写在 `afterCombine`。

`state` 是普通 JSON 对象，返回时整体替换自己的旧状态。可以记录资源数量、解锁、计数和自定义数据，但不能借它直接修改游戏统计或删除已有发现。避免保存循环引用、函数、非有限数、原型字段。`message` 是不超过 240 字的单行文字，不执行 HTML；玩法动作的提示显示在 Mod 面板，合成钩子的提示目前只保留为接口返回值，合成反馈仍使用游戏自己的结果提示。

脚本不可使用 DOM、Node.js、原生桥接、网络、其他 Worker 或本地数据库，也不能请求 Key。单个钩子超过约 1.5 秒会终止。代码异常不会自动改成收费 AI 请求。AI 已有答案时，先保留原始答案；脚本失败后由玩家明确点重试保存来保留原答案，避免为了同一次合成再次付费。

## 存档、更新与分享

每个存档有自己的 Mod 列表、启用状态和脚本数据。新安装或替换同 ID 的包默认停用；替换保留脚本状态，作者需要自行兼容旧状态。移除/停用不删除已经发现的卡、配方和历史。

导出 `.wxgc3-save` 会携带该档全部 Mod、脚本、资源与状态。朋友导入后获得新存档，不覆盖自己的档；整档包含已启用脚本时，导入确认会明确提醒。API Key 不包含在导出中。脚本包应在阅读说明、信任来源后启用。


## 当前容量边界

每包最多 4 MiB，16 个包/档；单资源 512 KiB、最多 32 个资源；脚本 128 KiB、状态 64 KiB；每包最多 200 张内容卡、50 张初始卡、1000 条固定配方、每类 20 个外观、12 个动作。整个存档含资源最多 32 MiB。上限用于控制手机加载和分享大小，不是这些上限同时占满时的性能承诺。

要添加独立界面或修改合卡操作，可从[源码目录](../README.md#修改游戏)入手。
