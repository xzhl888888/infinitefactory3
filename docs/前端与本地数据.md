# 前端与本地数据

游戏共用一套前端，Windows 使用 Electron，安卓使用 WebView。前端不能读取 API Key，模型请求、凭据和本地数据库通过平台接口处理。

## 画面与输入

正式入口是 `src/main.js`。首次确认使用协议后，创建本地控制器、管理面板以及画布运行时。

`src/legacy/` 保留《无限工厂2》的经典脚本结构，以便直接使用成熟的画面和操作。

- `categories.js`：卡牌分类与颜色。
- `engine.js` 负责画布适配、绘图、音效、命中检测、场景管理和重绘调度。
- `music.js`：背景音乐的 Web Audio 音序器。
- `home.js` 管理主页、当前档的发现数量和原有彩蛋。飘落图案、金色工厂和入口扫光使用 CSS 动画。
- `factory.js`：台面、拖放、词典、收藏、详情、分享、合成等待和结果动画。
- `runtime.js`：按顺序加载脚本，管理暂停、销毁及 Mod 媒体缓存。
- `bridge.js`：把当前本地存档投影为场景使用的数据，接收操作意图。

场景之间共享绘图变量，按经典 script 顺序执行。不要直接把它们分别改成 ES 模块，也不要在外层再次转发 pointer 事件，以免重复处理拖拽。管理面板使用 `src/ui/management-view.js`，负责 API 配置、多存档、Mod、合成历史、配方表与提示词编辑。

默认工作台静止时停止定时重绘。拖放与滚动随输入更新，等待合成的卡背约每秒重绘 15 次。发现动画播完后停在结果画面。台面卡牌的位置在松手时保存。

二代的账号、好友、战令、广告、等级、经济和全服数据接口不在运行路径中。兼容接口保留部分旧名称，但只投影三代当前本地存档；新项目的运行和构建不需要二代工程。

## 业务状态

`src/controller.js` 负责当前存档、原生请求、待存答案、Mod 钩子及保存顺序。画布上的选中、拖动、缩放、展开与动画归界面负责。卡牌、配方、收藏和统计以成功保存的状态为准。

每次合成使用稳定 operationId，最多四组不同材料并行。场景的 `combineAndWait` 只有在操作已经持久提交后才完成，因此动画不会先展示尚未保存的成功结果。已经收到的有效答案保存在本机待存日志中，重试保存不会再次调用模型。

多路答案可以乱序返回。Mod 处理按提交顺序读取最新玩法状态，防止后到的保存覆盖先前进度。恢复和切换存档会更新身份，旧回调不能写到新槽。

## 修改与验证

逻辑和接口检查使用 `npm test`。构建与源码一致性检查使用 `npm run build:web` 和 `npm run check`。原生打包方法见项目 README。

交互修改还需要通过正式应用入口验证。浏览器内的模型夹具用于控制等待、失败、取消和乱序，不代表真实供应商响应速度；桌面模拟触摸也不能代替安卓系统里的实际触摸。请使用新的测试存档，保留玩家自己的进度与 API 配置。

游戏版本号维护在 package.json、原生清单和 src/content/catalog.js 的 GAME_VERSION；源码检查会核对它们。主页的版本角标使用同一值，保留原来的小纸条彩蛋。
